# Phase 25D1E5 — Genel Buffett XSS sertleştirmesi ve deterministik Cloudflare Pages çıktısı (ÇEVRİMDIŞI, DAĞITIM YOK)

Cloudflare/Oracle/Supabase üzerinde hiçbir kaynak oluşturulmadı; gerçek veri, hesap, kimlik bilgisi yok. Üretim hazırlığı iddiası yoktur.

## 1. Bulgu ve düzeltme
`frontend/buffett/js/ui.js` AVAILABLE dallarında şablon-literal HTML'i `innerHTML` ile atıyordu (ticker, şirket adı, LLM analizi, değerleme alanları, geçmiş neden/tarih/ticker). Backend bugün yalnızca UNAVAILABLE döndürdüğü için sömürü gösterilmedi; ancak nitelikli veri açılmadan önce giderilmesi gereken kod düzeyinde bir enjeksiyon tehlikesiydi.
Düzeltme: tüm dinamik değerler önce doğrulanır, sonra yalnızca `textContent` ile, bu dosyanın kendi oluşturduğu elemanlara yazılır; statik CSS sınıfları kullanılır; veriden `style/attribute/href/src/HTML` alınmaz; satır içi stiller sınıflara taşındı; tek dinamik stil (`width`) doğrulanmış/sıkıştırılmış sayıdan CSSOM ile yazılır. Eksik/biçimsiz kanıt **sıfıra, NaN'a, Infinity'ye çevrilmez**: kayıt "Geçersiz kanıt" olarak, hiçbir rakam göstermeden işaretlenir, komşu kayıtlar çalışır; liste dizi değilse UNAVAILABLE (geçersiz kanıt) gösterilir (EMPTY değil). Drawer: ayrıntılar eksik/biçimsizse "Ayrıntılar doğrulanamadı"; veto bayrağı boolean değilse "Veto durumu doğrulanamadı". Geçmiş: `action` yalnızca `ADDED|REMOVED` allowlist'i; diğeri geçersiz kanıt. UNAVAILABLE yolu değişmedi (uyarılar da yalnızca metin).
**Güvenli oluşturma ≠ canlı kanıt:** testlerdeki AVAILABLE yükleri açıkça etiketli sentetik MOCK fixture'lardır; hiçbir kaynak nitelikli sayılmaz, canlı kanıt UNAVAILABLE kalır.

## 2. Genel Cloudflare Pages paketi (`scripts/buffett_cloudflare_build.mjs`)
Pages ayarları (ayrı proje, depo kökünden build): Root directory boş · Build command `node scripts/buffett_cloudflare_build.mjs` · Output `deploy/buffett-cloudflare/dist` · isteğe bağlı sır olmayan değişkenler `BUFFETT_OWNER_ORIGIN`, `BUFFETT_PUBLIC_ORIGIN`.
Çıktı (9 dosya, açık allowlist, `frontend/` özyinelemeli kopyalanmaz): `index.html` (kök açılış sayfası), `css/styles.css`, `js/{owner_entry,owner_entry_config,api,ui,app}.js`, `404.html`, `_headers`. Sahip HTML/CSS/JS, MFA, SDK, özel uygulama, eski kimlik doğrulama, backend, migrasyon, fixture, kimlik bilgisi, service worker, `_redirects`, Function/Worker **yok**; build yasaklı içerikte (sink, satır içi betik/stil, harici URL/yazı tipi, kimlik doğrulama/Supabase izi, sahip referansı, form) başarısız olur. Deterministiktir (zaman damgası yok; iki build bayt-bayt aynı).
Yazı tipi: Google Fonts bağımlılığı **kaldırıldı** (üçüncü taraf istek/gizlilik yüzeyi; CSS'te sistem yazı tipi yedeği). CSP bu sayede `font-src 'self'`, `style-src 'self'`.

## 3. Sahip girişi hedefi (derleme zamanı)
`{origin:null, path:'/owner/'}` bilinçli olarak korunur (ana makine adı icat edilmedi) → bağlantı devre dışı, `href` yok. Sonradan yalnızca gözden geçirilmiş **tam https origin** ile ayarlanır: `BUFFETT_OWNER_ORIGIN` (veya `--owner-origin=`), yoksa kaynak yapılandırmasındaki pinli değer. Doğrulama sayfanın çalışma zamanında kullandığı `owner_entry.js` doğrulayıcısıyla yapılır (https, yalnızca ana makine, port/yol/sorgu/parça/kimlik bilgisi/büyük harf/IP/localhost yok, `/owner/` yolu tam, genel origin ≠ sahip origin); geçersiz değer build'i **başarısız** kılar (sessizce null'a düşmez). Üretilen `js/owner_entry_config.js` küçük ve incelenebilirdir. Çevrimdışı koşum için loopback http hedefi yalnızca sayfanın kendisi loopback http ise çalışma zamanında kabul edilir; üretim bypass'ı yoktur.

## 4. Başlıklar ve 404
Tek `/*` kuralı: CSP (`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; base-uri/form-action/object-src/frame-src/frame-ancestors 'none'`; unsafe-*, joker, üçüncü taraf yok), HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, COOP/CORP same-origin, Permissions-Policy ve Pages'in varsayılan `Access-Control-Allow-Origin: *` başlığının kaldırılması. Üst düzey `404.html` zorunludur (yoksa Pages SPA sayar ve `/` içeriğini döner — belgeli); `/owner/*`, `/private/*`, bilinmeyen yollar 404 ölü sayfası döner. Yerel modelde doğrulandı; **gerçek Cloudflare davranışı dağıtılana dek doğrulanmamıştır** (`/owner` yönlendirmesi, 404 durum kodu/başlıkları, `_headers`'ın 404'e uygulanması varsayımları owner paketiyle aynıdır).

## 5. `/buffett/*` API yönlendirmesi — AYRI ÜRETİM KAPISI
Frontend `GET /buffett/portfolio` ve `/buffett/history` çağırır. Pages `_redirects` proxy'si yalnızca site içi göreli yolları destekler (harici alan adını proxy'leyemez; Cloudflare belgeleri), bu yüzden uydurma bir Oracle ana makine adı, `_redirects` proxy'si, Worker veya genel CORS genişletmesi **eklenmedi**. Statik paket tek başına API'yi çalışır hale getirmez; API yoksa istek 404 alır ve arayüz UNAVAILABLE'da kalır. Gerekirse Worker/Tunnel/yönlendirme kuralı bağımsız güvenlik incelemesinden geçmelidir; Worker/Function yanıtları kendi başlıklarını üretmelidir (statik `_headers` onları korumaz); CSP `connect-src` ve backend CORS tam origin ile birlikte güncellenir.

## 6. Genel çıktı için operatör prosedürü (YÜRÜTÜLMEDİ)
1. Ayrı Pages projesi (sahip projesinden farklı alan adı). 2. Ayarlar: yukarıdaki build/çıktı. 3. Sahip origin'i belirlendiğinde `BUFFETT_OWNER_ORIGIN` ve `BUFFETT_PUBLIC_ORIGIN` ortam değişkenleri. 4. Dağıtılan SHA'yı kaydet. 5. Anonim GET/HEAD: `/` 200, `/index.html` → `/`, varlıklar 200, `/owner/`, `/private/*`, `/buffett/*`, `/api/*`, bilinmeyen yollar 404 (gövde ölü sayfa), tüm yanıtlarda başlık seti. 6. Temiz tarayıcı: CSP ihlali yok, harici istek yok, service worker yok, depolama boş, "Sahip Girişi" yapılandırıldıysa tam `https://<sahip>/owner/`. 7. Geri alma: projeyi duraklat/sil veya alan adını kaldır.

## 7. Açık üretim kapıları
Canlı Cloudflare projeleri/alan adları; `/buffett/*` → Oracle yönlendirmesi (+CSP/CORS); Oracle dağıtımı; gerçek Supabase sahip hesabı ve iki TOTP; Migration 032; HS256/service-role geçişi; idempotency; WebSocket; `/api/metrics`; eski SPA XSS; nitelikli Buffett kanıtı (AVAILABLE dalı üretimde kapalı kalır).
